# Eurovision Data Analysis

Data-driven analysis of Eurovision voting patterns and song lyrics: voting-bloc
clustering and network analysis (`voting_blocs/`), general Eurovision
visualizations (`graphs/` → `output/`), and a BERT-based lyric-theme
classifier (`model/`). Supports the report in `paper/main2.tex`.

## Setup

```bash
pip install -r requirements.txt
```

## Running everything

```bash
python3 run_pipeline.py
```

This regenerates every table, report and figure in the repo, in dependency
order:

1. The 7 `voting_blocs/voting_blocs_*.py` scripts (similarity → clustering →
   graph → inference → causal → recsys → method comparison), writing into
   `voting_blocs/outputs/`.
2. `model/update_theme_predictions.py`, writing into `model/theme_predictions.csv`.
3. The 10 `graphs/*.py` visualization scripts, writing into `output/`.

`graphs/composer.py` pulls its dataset live from `raw.githubusercontent.com`,
so it needs internet access; the pipeline treats it as optional and continues
if it fails.

### The BERT step is skipped on purpose

`model/generate_themes.py` runs a zero-shot BERT classifier over every song's
lyrics to produce `model/theme_predictions.csv`. It is **not** run by
`run_pipeline.py` because it's slow (one model pass per song). The pipeline
uses the already-committed `model/theme_predictions.csv` instead. Only
re-run it if you've changed the underlying lyrics data or the theme list:

```bash
python3 model/generate_themes.py
python3 model/update_theme_predictions.py
```

The richer, 100-feature lyric-theme files (`test_lang/.../eurovision_enriched1.csv`,
`voting_blocs/eurovision_enriched2.csv`) were produced the same way (BERT
zero-shot, one pass per song) by a Google Colab notebook that is no longer
part of this repo. Both CSVs are committed pre-computed; there's nothing to
re-run unless you need to regenerate them from a new notebook.

## Layout

- `voting_blocs/` — voting-bloc similarity, clustering, graph-community
  detection, causal inference and recommender analysis. Self-contained: all
  its scripts, shared helper modules, and input data live here.
- `graphs/` — one script per chart in `output/` (composer stats, jury vs.
  public bias, kingmaker/tastemaker analysis, lyric themes, word clouds,
  etc.).
- `model/` — lyric-theme classification (BERT) and a song-score predictor.
- `test_lang/lyrics_nmf_topics_standalone/` — a separate, standalone NMF
  topic-modeling exploration over the lyrics; not part of `run_pipeline.py`.
- `paper/` — the project report (`main2.tex`) and its figures (`figures2/`).
- `eurovision_1957-2021.csv`, `eurovision-lyrics-2025.json` — shared source
  datasets used by both `voting_blocs/` and `graphs/`.

## Data provenance

`main2.tex`'s dendrogram, network-comparison, silhouette/cluster/modularity/
compactness tables, and method-agreement table all come straight from
`voting_blocs/outputs/`; regenerating them via `run_pipeline.py` reproduces
them byte-for-byte. Its jury-vs-public-bias and theme-distribution figures
come from `output/`, generated by `graphs/jury_vs_public_bias.py` and
`graphs/theme_pie_comparison.py` respectively.
